# System demo recording checklist

## Before recording

- [ ] Use the current independent review candidate identified by `submission/manifest.md` (or the accompanying manifest in an extracted ZIP). Verify the delivered file hashes and run the delivered tests. Source, tests and the coverage tool include reviewed changes; an old commit and an empty diff are not release criteria. An extracted ZIP needs no Git metadata.
- [ ] Create a new empty demo directory, start the CLI from it, and keep that directory for both Python processes.
- [ ] Rehearse the exact two sessions in `demo-commands.txt`; compare the visible results with `demo-expected-output.txt`. The printed absolute snapshot path will reflect the chosen directory.
- [ ] Arrange a readable terminal view and confirm the microphone and screen capture include the whole prompt and outputs.

## During and after recording

- [ ] Show creation of representative PIRs, `show`/`list`, a compound criterion and its search results, update, delete, save, a new process, load, and restored data.
- [ ] Record the system demo as **MP4** and measure the actual file duration. The official maximum is **4:00**; no duration is claimed before recording.
- [ ] Play back the MP4 to check commands, output, audio, readability, and that the second process genuinely starts anew.
- [ ] Use the separate presentation checklist for its **5:00** maximum and the official requirement that each member speaks for at least **1:00**, shows student ID card and face at the start of their turn, and remains visible while speaking. Verify those conditions on the real presentation recording.
